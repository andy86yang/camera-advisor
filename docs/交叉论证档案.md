## 3. 逐题回答

> 出处编号见第 6 节。**核实状态**分四档：`【亲自复核】`=主代理打开原始页或用官方 API 查过；`【子代理检索】`=检索子代理返回、主代理未逐条打开；`【未核实】`=查不到 / 无足够独立来源；`【推断】`=我的归纳，不是来源原文。

### Q1 · 整体怎么设计 → **三个盒子分开装**

**结论**：不要做成「一个 AI 直接吐答案」的黑箱。拆成三个互不干扰的盒子：

| 盒子 | 装什么 | 多久变一次 | 谁负责 |
|---|---|---|---|
| A 问问题 | 问卷（预算、拍什么、能不能接受二手…） | 几乎不变 | 人填 |
| B 打算盘 | 打分规则 + 机身/镜头规格库 | 半年到一年 | 人审，Git 留痕 |
| C 看价签 | 每次抓到的价格**观测记录** | **每天 / 每次大促** | 机器人自动跑 |

**为什么**：用户原话「不可能毕其功于一役，以后一定会有更新会有变化」——变的**只有价签**。把会变的东西单独关在一个盒子里，软件本体就不用改了。这是回答 Q6 的地基。

**AI 放在哪**：只放在 A→B 之间，干一件窄活——**把大白话需求翻译成打分用的「需求向量」**（例：「我想拍女朋友、不想修图」→ 需要 `直出肤色友好 + 人眼对焦 + 大光圈人像镜头可得`）。排序本身由 B 的透明规则算，不由 AI 拍脑袋。这样「AI 出错」也不会污染排序，且每一步能审计。

**出处**：架构为【推断】（基于 Q5/Q6 的检索结论归纳）。可解释打分的现成范本见 `05` 的 `mdkefir/decisionkit`【亲自复核：GitHub API】。

### Q2 · 输入端问什么

**结论**：问 8 项，每项都直接对应 B 里的一个可计算字段，不问废话：

1. 总预算（**含镜头**，不是只含机身）→ `budget_cap`
2. 主要拍什么（可多选：人像 / 视频 / 风光 / 街拍 / 旅行 / 生态打鸟 / 静物）→ `scenes[]`
3. 画幅偏好（全画幅 / APS-C / M43 / 都行）→ `sensor_pref`
4. 能不能接受二手 → `accept_used`
5. 能不能接受港版 / 水货 → `accept_grey`
6. 是否「直出 JPEG、基本不修图」→ `jpeg_only`（**这一项决定富士/佳能类「色彩」规则是否生效**）
7. 在意什么（防抖 / 轻便 / 对焦 / 视频规格 / 颜值操控）→ `priorities[]`
8. 所在省份 + 是否有国补资格 + 有无旧机置换 + 是否 PLUS/88VIP → `subsidy_context`（**这一组决定「你自己的到手价」**）

**依据**：`jpeg_only` 之所以必须单列，是因为富士胶片模拟与佳能肤色优化的已核实作用范围都**只在 JPEG/HEIF，不影响 RAW**（S12、S13、S14）。不问这一项，规则就会误用。`subsidy_context` 是因为 15% 数码国补有地区、单价上限、品类、每人类限一次的限制（S20、S21）。

**核实状态**：`【亲自复核】` S12/S13/S14 中 RAW 不受影响由富士相关来源支持；国补限制 `【子代理检索】` S20/S21；字段设计为 `【推断】`。

### Q3 · 口诀能不能直接当规则 → **不能，要降一级**

**结论**：`拍人→佳能` 这种 if-then 有四个毛病：①有的已被证伪（见 Q13/P6）；②有的是主观审美，不能量化；③有的只在特定条件成立（直出 JPEG、二手语境）；④有的漏候选。

**正确写法是两层**：
- 第一层：把口语需求翻译成**机器属性**（不是品牌）。例「拍视频多、在乎防抖」→ `IBIS 档数 ↑`、`无限录制 ↑`、`Log/LUT 工具 ↑`、`10-bit 4:2:2 ↑`，**而不是**「选松下」。
- 第二层：每台机器有一组带出处的属性分，加权求和排 Top 3。品牌口诀降级为**小额加分项**，且每条挂一个「证据等级」标签（A 硬指标 / B 厂商一手 / C 多源共识 / D 口碑 / E 未核实）。**D 级和 E 级不许单独决定推荐**。

**输出必须带三样**：为什么推荐它 / 为什么不推荐另外两个 / 这条结论的证据等级和出处。

**出处**：规则表见 `04_选购知识库_规则与证据.md`；加权打分范本 `mdkefir/decisionkit`【亲自复核】；品牌命题核查 S1–S11 `【子代理检索】`。

**结论（重要，请交叉论证重点复核）**：**目前不存在一个「公开、合规、稳定、覆盖二手+港版、还直接给到手价」的 API。** 逐源结论：

| 数据源 | 有没有官方读价 API | 能不能拿到「到手价」 | 主要麻烦 | 状态 |
|---|---|---|---|---|
| 京东商品页 | 未找到公开读价 API | 挂牌价（价格 JS 登录态加载、服务端混淆） | 需 cookie，直抓风险高 | S22 `【子代理检索】` |
| 京东联盟 API | **有**（需实名+AppKey+推广位） | 返回原价/促销价/**券后价**，≠最终实付 | CPS 导购约束，用途须与申报一致 | S23 `【子代理检索】`；QPS 等第三方数字**已剔除不采信** |
| 慢慢买 / 历史价格 | **无官方 API**，但有逆向免签通道 | **有 `final` 字段 = 到手价（含满减/券）**，另有 30 天最低 | 逆向通道不稳定，随时可能失效；合规需守 robots.txt | S24 `【子代理检索】` |
| 什么值得买 | 未找到公开价格 API | **不是结构化价格**，是社区爆料帖 | 只能人工校验，构不成价格序列 | S25 `【子代理检索】` |
| 闲鱼 | 无公开免费 API（`item_get` 需企业资质） | 二手挂牌价 | **12 个源里反爬与合规风险最高**：mtop 签名、token 24h 失效、设备指纹、滑块 | S26 `【子代理检索】` |

### Q5 · 发售价 vs 到手价

**结论**：差价是**逐层扣减**出来的，不是两个数相减那么简单。已核实的实例（均为时点快照，带观测日）：

| 机型 | 发售价 / MSRP | 到手价 | 差额构成 | 出处 |
|---|---|---|---|---|
| 索尼 A7C II 单机 | 13999 元（2023-08 首发） | **8091.15 元**（2026 双 11） | 15% 国补 + 直播间 600 元券 | S20 `【子代理检索】` |
| 索尼 A7 V（A7M5） | 17999 元（2025-12-02 首发） | **13799 元**（11.11） | 500 券 + 直播间 1000 券 + 首购立减 1896 + 15% 国补 | S21 `【子代理检索】` |
| 尼康 Z5 II C | 9999 元（发布定价） | 约 **7900 元** | 双 11 国补 | S21 `【子代理检索】` |
| 富士 X100VI | 11390 元（2024-02 首发） | 2026 双 11「9000 出头」 | 产能放量 + 百亿补贴 | S21/S32 `【子代理检索】` |
| 佳能 EOS R8 | $1,649 列表价 | **$1,399**（2026-10-30~11-01） | 厂商 instant savings | **S1【亲自复核】** |

**扣减链条**【推断，非来源原文】：
`渠道挂牌价 → 平台券/跨店满减 → 国补（受地区/单价上限/品类/名额约束）→ 会员权益（PLUS/88VIP）→ 直播间券/支付立减 → 以旧换新抵扣 → 晒单返 E 卡/赠品（隐性折现）`；**再加运费**（二手市场运费不可忽略）。分期免息不改名义价格，只改资金成本。

**关键转换**：所以「到手价」不是查来的一个数，是 `价格观测 + 用户条件 + 一串扣减公式` 算出来的。软件必须把公式摊开显示。字段级定义见 `03_价格数据契约.md`。

**反例警示**：S33（shouldyoubuythiscamera）**【亲自复核】** 显示富士 X100VI 同一时期四组数字互相冲突——国内回收价 8100 / 9900 元、国内双 11 成交「9000 出头」、美国二手 $1,768–$2,289。成因是**地域 + 时点 + 渠道（新机成交 / 二手挂牌 / 回收商收价）+ 成色等级**不同。所以任何价格入库必须带这四元组，缺一即视为幻觉风险。

### Q6 · 怎么让它一直自动更新（用户最纠结的一题）

**结论**：四招叠加，核心是**「不维护软件，只维护一张表」**：

1. **价格表独立成文件**（如 `data/prices.json`），软件代码里**一个硬编码价格都不留**。改价格 = 改表，不动程序。
2. **GitHub Actions 定时跑**（免费）：每天（大促期间每小时）跑一次采集脚本 → 生成带 `observed_at` 和 `source_url` 的新观测 → 自动 commit 回仓库。仓库自己会长大，还会留下一整条历史曲线。**这一步就是用户说的「一直维护」的答案：维护者是机器人，不是人。**
3. **抓不到就老实说不知道**：任何一条价格超过 `stale_after_days`（建议新品 7 天、二手 3 天、大促 1 天）没更新，界面显示「价格已过期，最后观测于 YYYY-MM-DD，请自行核对」，**绝不用旧数冒充新价，更不让 AI 编一个数**。这是防幻觉最要紧的一条。
4. **两条兜底**：① 用户手填自己刚查到的实付价（顺手可提交 PR 回仓库，开源的优势）；② 社区用 Pull Request 改表，每次改动留 Git 记录可追溯。

**为什么「毕其功于一役」不可能、也不必**：用户原话说得对，价格永远在变。但正因为如此，正确目标不是「把价格一次做全」，而是「**让『价格会变』这件事变成系统的正常状态**」。软件默认价格随时可能缺失/过期，仍能给出「按发售价粗估 + 明确标注未核实」的降级结果。

**出处**：机制为 `【推断】`；可行性依据 = Q4 各源 + S33 的「观测日 + 逐源链接 + 90 天价格史」现成范式**【亲自复核】**；`shouldyoubuythiscamera` 页面自述「nightly crawl」「One point per day per (source, grade) pair」，并提供了标准引用格式 `Cite ..., observed 2026-11-22, URL`——**这套数据契约直接抄过来即可**。

### Q7 · 二手 / 港版怎么摆

**结论**：两者**不在同一个坐标系**，不能混着比价。

- **二手**：定价靠 `成色等级 + 快门数 + 维修史 + 配件完整度`。KEH 官方分级页明确「Grades are based on cosmetic attributes and not on functionality」【S28，官方一手】；MPB 5 级成色 + 标快门数 + 6 个月保修【S27】。国内回收商报价也按「99 新、原装电池充电器齐全」分级，且原文提示「参考价不等于每台机器的成交价」【S34】。→ 系统里二手价必须挂 `condition_bucket` / `shutter_count` / `warranty_status` 三个字段。
- **港版 / 水货**：**保修风险已核实**。佳能中国官网保修条款原文：「数码相机及数码摄像机执行国家相关三包规定（**但仅限于在中国大陆地区购买的产品**）」「请出示保修卡及购机发票进行保修」「本保修制度**仅限在中国大陆地区、香港和澳门特别行政区有效**」「保修卡遗失不再补发」——**【S35 亲自复核】**。另有厂商公告称不符合规定进口的产品无法享受免费保修【S36】，中国消费者报 2015 年引索尼中国售后称水货不能享受联保【S37，旧文】。风险清单：仅店保（店倒即失效）、无国补资格、无法官网注册/延保、翻新/换配件、刷机改中文冒充国行、二手转售折价【S38/S39】。
- **「港版一定便宜」不成立**：来源指出佳能采「税后全球统一价」定价策略，港行价差被抹平；且国补只给国行，大促后国行到手价可能更低【S39，2013 年旧文，其中「17% 消费税」为旧税率，现行税率未核实，不入库】。
- **「尼康 + 港版」的绑定查不到任何独立来源**，且被上述定价逻辑反证 → 标 `【未核实】`，不写进规则库。

**设计动作**：`accept_grey = true` 时，系统不给港版套用国补公式，并强制弹一条保修风险提示；`accept_used = true` 时，报价旁必须显示成色等级和观测日。

### Q8 · 机身 + 镜头怎么组合

**结论**：
1. **先定卡口，再选镜头**：机身库里每台机器写死 `mount`（RF / Z / E / L / X / M43…），镜头库写 `mount` + `sensor_coverage`（全幅 / APS-C）。跨卡口不兼容的直接过滤，避免「推荐了 RF 机身配 Z 镜头」这种低级幻觉。
2. **镜头数据可复用开源库**：`lensfun/lensfun` 的 `data/db` XML 有 mount/camera/lens 对应关系【亲自复核 GitHub API：896 star, LGPL-3.0】；机身规格可用 `leavestylecode/CameraDatabase`（3860 台、37 字段 CSV/JSON）【亲自复核：86 star, MIT】。
3. **预算按「整机套」算**：`机身实付 + 镜头实付 + 必需配件（电池/卡/包）≤ budget_cap`，并在结果里显示各占多少。用户原话强调「机身和镜头的价格」，所以**不能只报机身价**。
4. **镜头也要带价格观测**：同一支镜头不同卡口不同价，必须按 `model_id + mount` 分开存（S33 的 Methods #1.5 明确讲了这点【亲自复核】）。
5. **许可证坑**：`Luminoid/lens-db` 是 CC BY-NC-SA（非商用），`lensfun` 数据是 CC BY-SA（有传染性）。用户不商用 → NC 可用；但放 GitHub 时衍生数据要守 SA，见 `05`。

### Q12 · 「AI 不收广告、不偏见、客观」成立吗 → **不成立，但可以补救**

**结论（这条我得直说）**：AI 确实不收广告费，但**它有偏见**，而且偏见来源恰恰是你想蒸馏的那批博主内容——训练语料里全是「拍人佳能、视频松下」这类口径，其中不少来自恰饭视频和导购站（affiliate 佣金）。所以「用 AI」本身**不等于**客观。

**客观性真正来自三件事，跟用不用 AI 无关**：
1. **规则透明**：排序是加权求和，权重表里每一行都能点开看见，不是模型一句话；
2. **来源可追溯**：每条规则、每个价格都挂 URL + 观测日，能被人打开复核；
3. **可交叉验证**：档案自包含，能整份丢给第二个、第三个模型挑错（也就是你现在在做的事）。

**还有两条硬规矩**：① 任何 affiliate 导购站的数据只当线索，不当事实；② 核查时已**剔除**几个疑似 AI 生成内容农场的精确数字（「E 口 1217 支原生 AF 镜头」「DPReview 2024 Lens Database Audit」「X100 系列维持 80–110% MSRP」「Acros 保留 92.4% 高光细节」等），因为找不到第二来源印证，一律不入库。

**出处**：剔除清单与理由见 `09_来源与核实记录.md` 末尾；Amazon PA-API 许可明文禁止「aggregating / repurposing / 训练 ML」【S30 `【子代理检索】`】也说明「拿别人数据喂模型」不是天然合规。

### Q14 · 怎么防幻觉 / 怎么组织给其他 AI

**做了 6 件事**：
1. 每个数字带**观测日**（价格会过期，不标日期就是耍流氓）；
2. 每条结论带 **URL + 发布方 + 年份**，年份页面没写就标「年份未标注」，不猜；
3. 区分 **【事实】/【口碑】/【推断】/【未核实】** 四档，推断不能当事实引用；
4. 关键结论要 **2 个互相独立的来源**，同一篇转载只算 1 个（已合并中新网转载、百科重合内容）；
5. **没查到就写「未核实 / 未找到」**，不用常识补空（如「尼康+港版」「松下色彩」）；
6. 主动**剔除**无法交叉验证的精确数字（疑似 AI 内容农场），并写明剔除理由。

**给其他 AI 的材料组织**：本文件自包含（原话 + 题目 + 回答 + 来源表 + 核实状态），另附 `08_给其他AI的吩咐_可直接复制.txt` 一段大白话提示词。**建议至少丢给 2 个不同厂商的模型**，让它俩互相挑，重点攻第 4 节和第 5 节。

## 9.3 逐题回答（结论 + 落到哪个文件）

**Q16｜「总结烂了」错在把阶段性共识当永恒定理。** 22/23 说一英寸一定优于略小底，25/26 手机纷纷选略小底 + 可变光圈 / 一镜双目 / RYYB / 计算摄影补总进光量，换动态范围、画质、帧率与适配度（**用户观点，我未独立核实**）。结论有**适用条件与时效**；可复用的不是结论，是**失效条件 + 复核机制**。这不构成「倒退」，恰是「不断自我革命」。→ `10` 第 0 节、`reputation.json Q10 = outdated`、`CONTRIBUTING.md` §3。

**Q17｜起点换成 P1。** 新增 `current_gear / existing_kit / pains[] / constraints[]`；`phone_battery` 触发「建议增加独立拍摄设备」，因为电量、时间、注意力与钱一样是稀缺资源。→ `10` P1、`engine/scoring.py:profile()`、网页第 1 组问卷。

**Q18｜P2 + P3。** 硬约束改为 `机身到手价 + 镜头 + 配件 ≤ 预算`，不满足**直接淘汰**而非降分；机身加 `role: transitional` 与升级路径。→ `M1`、`bodies.json` 的 `role`。

**Q19｜P4，直接改掉 v1 的机器人设计。** 价格从「大促抓一次」改为**每日持续采样 + 全历史只追加不覆盖**；加 `first_launch_price` 基线（首发溢价）、持有期折旧、以及「相对亏损参照系」（冲首发亏更多，所以不算十分肉疼）。→ `.github/workflows/update-prices.yml`、`price_history.json`、`10` P4、`docs/价格数据契约.md` §5。

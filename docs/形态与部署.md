# 形态与部署：什么已经是成品、什么还只是路径

> 用户明确说：「我感觉好像不是一个软件」「我想要直接做成一个成品」「做成网站在浏览器里用 / 做成小程序在微信里用 / 开源到 GitHub 别人下载就能用」。
> 这份文档不粉饰：**做完的写做完，没做的写清路径与边界，不建议现在做的直说不建议。**

---

## 0. 先回答「这算不算成品」

| 判据 | v1 | v2 |
|---|---|---|
| 双击 / 克隆后能不能直接跑出结果 | 能，但只是 8 项问卷 → 参数表 | ✅ 5 组问卷 + 6 个预设 → **画像 + Top3 + 补偿 + 白花钱 + 镜头 + 持有成本** |
| 输入一个人的真实条件是否自动跑 | 部分 | ✅ 现有装备 / 痛点 / 负重 / 身体 / 输出端 / 后期 / 社交全部进引擎 |
| 能不能联网、深度思考 | ❌ | ✅ **由 skill 形态完成**（真联网 + 五类来源交叉 + 出画像） |
| 能不能给别人用 | 只能发文件 | ✅ 静态站一键部署 / GitHub clone / skill 安装 |
| 有没有可维护机制 | 文档 | ✅ 每日抓价 Actions、每周口碑复核、issue 模板、重建脚本 |

**结论**：形态 **A（静态网页成品）** 与 **B（可安装 skill）** 已经是成品；
**C（带后端网站）**、**D（微信小程序）** 目前是**已给足实现路径、但尚未实现**的下一阶段。
下面逐条说清边界 —— 不假装做完，也不停在构思。

## 1. 五种形态对比

| 形态 | 现状 | 给别人用 | 联网 | 需要什么 | 成本 |
|---|---|---|---|---|---|
| **A 静态网页** | ✅ 已完成 `app/index.html` | GitHub Pages / 任意静态托管，打开即用 | ❌ 网页本身不联网（如实标注）；价格靠 Actions 更新 `data/` 后重新部署 | 一个静态托管 | 0 |
| **B 可安装 Skill** | ✅ 已完成 `07_camera-advisor-skill/` | 装进 WorkBuddy，对话即用 | ✅ **真联网 + 深度思考** | AI 运行环境 | 0（用已有环境） |
| **C 带后端网站** | ⬜ 未实现，路径见 §3 | 浏览器登录、可存画像 | ✅ | 服务器 / 域名 / 价格 API / 可选 DB | 有 |
| **D 微信小程序** | ⬜ 未实现，合规边界见 §4 | 微信内打开 | 受限 | **ICP 备案域名** + 类目审核 + 合法域名白名单 | 有 |

**分工不是缺口**：静态网页负责「离线、零门槛、谁都能算」，skill 负责「联网调研与复核」。
纯静态页面**不可能**真的全网搜价 —— 谁声称能做到，要么在偷偷调第三方，要么在编。

## 2. 形态 A · 把静态站发出去（现在就能做）

### GitHub Pages（最省）
```bash
git init && git add . && git commit -m "init: camera-advisor v2"
git remote add origin <你的仓库地址> && git push -u origin main
```
仓库 Settings → Pages → Source 选 `main` / `/docs` 不行，因为入口在 `app/`。
两种办法：
- 把 `app/index.html` 复制一份到仓库根 `index.html`（一行 `cp app/index.html index.html`），Pages 选 `/ (root)`；
- 或在 `scripts/rebuild_data.py` 里把输出路径加一份根目录 `index.html`（推荐，重跑自动同步）。

Cloudflare Pages / Vercel / Netlify 同理：Build command 留空，Publish directory 填 `app`（或根）。

### 价格怎么跟着更新
`update-prices.yml` 每日采样 → commit `data/prices.json` → 静态托管自动重新部署 →
`rebuild_data.py` 把新数据重新注入 `app/index.html` → 用户刷新即见新价。
**软件本体一行不动**，符合「改价 = 换一张纸」。

> 部署前必做：把 `README.md` 的防幻觉声明保留在仓库首页；界面顶部红字「价格示例 / 非实时报价」**不许删**。

## 3. 形态 C · 带后端网站（路径，未实现）

### 什么时候才真的需要后端
- 要**实时到手价**（不是示例价）→ 需要服务端抓价或对接合法 API
- 要**保存用户画像 / 多设备同步 / 历史对比** → 才需要 DB 与登录
- 只是「填条件算一次」→ **静态站够用，别为了「像软件」硬加后端**

### 最小改造（约 30 行）

目录扩展：
```
camera-advisor/
├── services/price_api.py     # 新增：只读数据 API
├── app/index.html            # 改成支持 ?live=1
└── data/                     # 不变，仍是唯一数据源
```

`services/price_api.py`（FastAPI，只读、无写库）：
```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
import json, os
app = FastAPI()
app.add_middleware(CORSMiddleware, allow_origins=["*"], allow_methods=["GET"])
DATA = os.path.normpath(os.path.join(os.path.dirname(__file__), "..", "data"))

@app.get("/api/data")
def get_data():
    names = ["bodies", "rules", "lenses", "reputation", "price_history", "prices"]
    return {n: json.load(open(os.path.join(DATA, n + ".json"), encoding="utf-8"))
            for n in names}
```

前端在 `app/index.html` 里把注入点改成「内嵌兜底 + 可选 live」：
```js
let DATA = /*__DATA_V2__*/;                    // 离线内嵌（file:// 也能跑）
if (location.protocol.startsWith("http") &&
    new URLSearchParams(location.search).get("live") === "1") {
  fetch("/api/data").then(r => r.json()).then(d => {
    DATA = { bodies: d.bodies.bodies, rules: d.rules, lenses: d.lenses.lenses,
             reputation: d.reputation.reputation, price_history: d.price_history.series };
    // 重新 chips / 重跑 run()
  }).catch(() => console.warn("live 数据不可用，已回落到内嵌示例数据"));
}
```
**关键**：`file://` 下 fetch 会被拦，所以内嵌兜底必须保留 —— 这正是「双击就能开」不破的原因。

### 再往后（真要上线时）
- 抓价服务：把 `scripts/fetch_prices.py` 的 `NoOpSource` 换成合法适配器，由服务器 cron 或现有 Actions 触发
- DB：只有要存画像才上（SQLite 起步即可）；**能不收集个人信息就别收集**
- 登录：只在多设备同步时才需要；匿名可用是优点，不是缺功能
- 合规：抓价前确认目标站点 robots / 服务条款、是否需登录或 cookie、反爬风险；**任何分支都不许让模型编价格**

## 4. 形态 D · 微信小程序（合规边界，建议缓做）

这一段最重要：**小程序不是把网页套个壳就行**，平台规则比技术更硬。

| 约束 | 说明 |
|---|---|
| `wx.request` 合法域名 | 必须在小程序后台配置 **request 合法域名**，强制 HTTPS，且域名需 **ICP 备案**（中国大陆） |
| `web-view` | 若用内嵌网页，需配 **业务域名** + 把校验文件放到域名根目录；个人主体小程序可用能力受限 |
| 类目与资质 | 涉及「电商平台 / 导购比价」类目要求更严；本项目不交易、不导流，按「工具 / 效率」类目最轻 |
| 包体积 | 主包 2MB 上限。当前 `data/` 约 100KB 可整包打入；但**实时价格必须走已备案域名 API**，不能打包 |
| 不能爬电商 | 小程序端抓取电商页面违反平台规则与站点条款，别做 |
| 价格展示 | 未接合法源之前，界面必须保留「示例 / 非实时报价，禁止用于下单」红字 |

### 两条可行路径
1. **离线工具版（最轻，可先做）**：把题库、规则、示例价打进小程序包，价格一律显示「示例，请自行核实」；
   不接任何外部域名 → 备案 / 白名单 / 抓价合规问题全部绕开。
2. **已备案域名 API 版**：先完成形态 C 的后端与备案域名，再在小程序里 `request` 该域名。

### 我的建议（实事求是）
**先做 A + B，C/D 等「真有人用、且价格源合法」了再做。**
理由：这个产品最难的不是界面，是「到手价持续、合法、可核实」。在价格源没解决前做小程序，
只会得到一个好看但不能给真实报价的壳 —— 恰恰是你批评的「停留在构思、没有实践」。

## 5. 形态 E · PWA / 命令行

CLI 已完成：`python engine/scoring.py --preset hiker`（零依赖）。

PWA 只需两步（可选，做了能「添加到桌面 / 离线缓存」）：
```json
// app/manifest.json
{ "name": "相机选购顾问", "short_name": "选相机", "start_url": "./index.html",
  "display": "standalone", "background_color": "#f5f7fa",
  "icons": [{"src": "icon.png", "sizes": "192x192", "type": "image/png"}] }
```
```js
// app/sw.js —— 只缓存静态资源，不缓存任何「实时价格」承诺
self.addEventListener("install", e => e.waitUntil(
  caches.open("ca-v2").then(c => c.addAll(["./", "./index.html", "./manifest.json"]))));
self.addEventListener("fetch", e => e.respondWith(
  caches.match(e.request).then(r => r || fetch(e.request))));
```
在 `index.html` 里 `<link rel="manifest" href="manifest.json">` 并注册 sw 即可（仅 http(s) 生效，`file://` 自动跳过）。

## 7. 一句话总结

**已经做完**：能双击的网页成品（A）、能装进电脑且真联网的 skill（B）、能 push 到 GitHub 给别人 clone 的自包含仓库（含每日抓价与每周口碑复核机器人）。
**给了完整路径但没做**：带后端网站（C）、微信小程序（D）—— 因为它们的瓶颈是「合法可持续的到手价数据源」，不是代码量。
**不建议现在做**：在价格源没解决前做小程序。

这比「先做个壳显得像软件」更接近你说的「实事求是」。
